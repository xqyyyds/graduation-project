但现在还存在的几个问题
问题一：Reduce prompt 还是有点“太会教写作了”

你现在的 Reduce 写得非常细，细到像一个写作教练。
这有好处，但也有副作用：

模型会明显感到“我在按指导作文”

结果可能变成一种“训练有素但略显用力的成品腔”

比以前不再是纪要体，但可能变成“深读模板体”

比如这类句子风险还在：

这起事件真正被点燃，不只是因为……

讨论随后从……滑向……

到周期末，事件暂时停在……

这些句子本身不坏，但如果每篇都这么写，就会有模板味。

怎么改

不是删要求，而是减少解释性元话语。
把一些“告诉模型怎么写”的句子，换成更少但更硬的禁令。

比如“事件概述”这一段已经够用了，没必要同时保留太多：

写作顺序要求

写法要求

首句要求

禁止横向罗列

时间嵌入方式

禁止标签句

这些全对，但叠太多时，模型会一边写一边“想着别犯规”，文气反而绷。

问题二：timeline_digest 很可能变成新的“半成品拐杖”

这取决于你喂进去的内容质量。

如果 timeline_digest 本身长这样：

那很好。

关键节点包括……

媒体态度……

官方回应待核实……

那 Reduce 还是会模仿它，最后又写回纪要体。

关键点

你最终写成什么，往往更像输入，而不是更像 prompt。

所以现在真正要盯的不只是模板，而是：
timeline_digest 这层是不是已经被你上游写成“事件推进线”，而不是“事件字段摘要”。

问题三：Map 还不够支持“事件概述”的叙事写作

你现在在 Map 里加了：

传播触发

扩散方向

很好，但你贴出来的 schema 还没跟上。
你现在的 PostOpinionSummary 还是只有：

opinion_clusters

conflict_analysis

如果 schema 没同步增加字段，Map 提示词里新增的“步骤6”最后不会稳定落进结构化结果，Reduce 也吃不到。

这会导致你以为“我让模型分析了触发点和扩散方向”，但实际上中间产物没有把这个信息稳定传下去。

我最建议你马上补的 schema

你 Map 既然已经写了“传播触发与扩散方向”，schema 就该补这两个字段：

class PostOpinionSummary(BaseModel):
    opinion_clusters: List[OpinionCluster] = Field(
        description="提取出的主要观点阵营（1-5个，视实际舆论分歧程度而定）及其占比"
    )
    conflict_analysis: str = Field(
        description="分析评论区的舆论对立程度。若存在激烈争论或群体冲突，请指出核心矛盾点；若氛围和谐，填'无'。"
    )
    trigger_summary: str = Field(
        description="这条帖子在本期讨论中最容易点燃传播的触发点。应指出具体是截图、爆料、回应、价格变化、身份信息、情绪表达还是其他内容引发转发和跟评。"
    )
    propagation_hint: str = Field(
        description="评论区主要把议题往哪个方向推大或推深，例如从个案质疑滑向平台责任、从消费吐槽滑向监管讨论。"
    )


这一步很重要。
不然 Reduce 只能继续靠 timeline_digest 单线程写发展过程。

现在这版 Reduce 还差一个最关键的“坏句式黑名单”

你虽然已经写了：

不要使用“事件概况：”

不要写成“研判周期：”“关键节点与处置：”……

但我建议你再加一段更直接的黑名单，因为你们现在的失败模式已经很稳定了。

可以加在 event_overview 那部分最后：

生成 `event_overview` 前，先检查并避免以下坏句式：
- “在本研判周期内……”
- “研判周期：……”
- “核心事实是……”
- “关键节点与处置如下……”
- “讨论点包括……”
- “媒体与平台态度是……”
- “主流讨论集中在……”
- “事件概况如下……”

如果你的段落像在给内部材料分栏摘要，而不是在向读者讲清事件如何一步步发展，请重写。


这招非常实用，因为你们现在不是“偶尔不顺”，而是“老是掉进固定坑里”。

还有一个细节：public_opinions 固定四条没问题，但建议前缀写死

现在你写的是：

固定输出 4 条，按顺序对应：主流声浪、次生质疑、深层情绪、对立博弈

这不错，但为了防止输出变成 4 条普通句子，建议把每条的开头格式也锁一下：

- 第1条必须以“主流声浪：”开头
- 第2条必须以“次生质疑：”开头

这样用户一眼就能看懂，而且不会变成杂乱列表。

depth_analysis 现在还会有两个风险
风险 1：仍可能偷复述概述

虽然你已经写了“禁止复述”，但这类 prompt 常见问题是：
模型会换个说法再讲一遍“为什么爆、怎么传播”。

建议在 depth_analysis 里再补一刀：

`depth_analysis` 不得重复出现事件中的具体时间点、帖子传播过程、回应顺序、截图传播链条等事实性叙述；这些内容只能出现在 `event_overview`。


这样能更明确切层。

风险 2：容易写成“社会意义万能句”

你已经禁止了：

折射出

引发广泛关注

值得警惕

值得深思

这很好。
但可以再具体点，让它必须回答两个问题：

第一段必须回答：为什么这件事会在本周期内集中炸开，而不是停留在零散吐槽层面。
第二段必须回答：为什么评论区会沿着当前方向演化，以及后续最可能外溢到什么更大的议题。


这比泛泛“社会意义”更可操作。
