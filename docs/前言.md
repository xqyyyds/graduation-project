前言这版，方向是对的，而且比你前面几个 agent 更接近成品。
但它也有一个很典型的问题：

你一边说“这是短前言、要像成品”，一边又给了太多“兼容字段”和写作说明，模型还是会隐约把它当成“多栏位压缩摘要”来写。

所以前言这里的核心不是“会不会写成纪要体”，而是：

会不会写得像前言

还是会写成正文缩写版

或者写成总述 + 风险提示的拼接稿

我的判断是：

现在这版能不能用？

能用，而且已经不错。

现在这版最容易出现什么问题？

不是“不通顺”，而是这三种：

第一段写得太像正文总述，不够“压缩型开篇”

第二段写得太像趋势预测摘要，把后文抢了

兼容字段太多，容易反向把正文拉回“摘要拼装感”

前言这块和前面几个模块不一样

前言最怕的不是“列表化”，而是：

1. 太像报告导读

比如：

本期主要涉及……

从舆情表现看……

风险方面主要体现在……

这种就很像内部导读，不像总编前言。

2. 太像正文压缩版

也就是把：

事件概述

观点画像

深度分析

风险预测

每个都压一句，最后拼起来。
这不是前言，而是目录摘要。

3. 太像概念判断

比如：

复杂性上升

风险交织

情绪分化

治理压力增大

这些词放一堆，读者知道“气氛很严肃”，但不知道这一期到底在吵什么、有什么新变化、为什么值得看。

你这版已经好的地方
1. 你把 paragraphs 定成主输出，这是对的

这点很重要。
只要 paragraphs 是主字段，前言就有机会像文章；否则就会被兼容字段拖成摘要体。

2. 你明确要求“第一段看榜单全貌，第二段压风险压力”

这个结构很适合前言：

第一段：像总编开场

第二段：像点风险收束

这是对的。

3. 你已经在防“写作过程痕迹”

比如禁止：

判断：

总体来看：

第一段要点在于

这些都很有效。

但这版还差 5 个关键收口
一、前言最需要的不是“覆盖信息”，而是“抓住本期主轴”

你现在虽然写了：

必须从输入里提炼真正的主线矛盾

但还不够狠。
建议再明确一条：

前言不是把本期所有议题平均分配地写一遍，而是先抓住最能统摄全期讨论的一条主轴，再用少量次级议题衬出它的分量。若所有议题被平均着墨，说明主轴没有拎出来。


因为前言最怕“样样提到，样样不重”。

二、第一段还要禁止“从分类开始”

你现在要求“热点榜单全貌”，这没问题。
但模型很容易写成：

教育类议题主要集中在……

消费类议题主要围绕……

安全类舆情则体现在……

这还是“分类归纳”，不像前言。

建议补一句：

第一段不得按“议题A、议题B、议题C”平铺分类归纳，而要先给出本期最突出的共同张力，再自然带出几个典型议题作为支撑。


这样第一段会更像前言，而不是榜单解说。

三、第二段要防止“把后文预测写完”

你现在已经说：

必须自然包含“未来风险的详细推演，请见报告正文”

这个可以，但要小心。
因为模型很容易把第二段写成：

未来哪些风险

为什么会来

可能怎么发酵

需要关注什么

这样其实已经把 Agent D 的活干了。

建议加一句：

第二段只负责压出风险压力和治理难点，不负责展开未来情景推演。它应像“把读者带到门口”，而不是把正文里的预测内容提前写完。

四、兼容字段虽然可以保留，但要再强调“不得反向主导正文”

这是你这版的一个隐患。

因为模型看到：

overview

characteristics

compliance_perspective

trend_connection

conclusion

很容易脑内形成：

这还是老式五段摘要，只不过多了 paragraphs。

所以建议加一句：

兼容字段仅用于旧渲染链补位，不得反向决定 paragraphs 的结构与语气。若 paragraphs 像由 overview/characteristics/conclusion 拼接而成，视为写作失败。


这个非常重要。

五、前言需要一个“坏句式黑名单”

现在你的前言 prompt 已经很细了，但还是建议加一个非常直接的黑名单，因为前言常见坏味道很固定。

比如加：

生成 paragraphs 前，先避免以下坏句式：
- “本期舆情主要呈现以下特点……”
- “总体来看……”
- “从舆情表现看……”
- “一是……二是……三是……”
- “本期热点主要集中在……”
- “风险方面主要体现在……”
- “未来需重点关注……”
如果段落像报告摘要、导读提纲或工作小结，而不是压缩型综述前言，请重写。


这个会非常管用。

schema 这块，整体比前几个 agent 更稳

前言 schema 其实没太大问题。
因为主输出字段已经很明确：

paragraphs 是主体

其他都是兼容字段

这比 Agent D 那种多拆字段的风险小很多。

但我仍建议改两点：

1. paragraphs 的描述再狠一点

现在写的是：

输出1-2段自然成文的综述段落。第一段负责概括……第二段负责压缩……

建议改成：

paragraphs: List[str] = Field(
    ...,
    description="【主输出】前言成品正文，严格输出1-2段。必须像压缩型新闻综述前言，而不是报告导读、正文摘要或提纲拼接。第一段先拎出本期主轴，再自然带出议题分布与总体情绪；第二段只压缩风险压力、治理难点与未来关注方向，不得展开成正文分析。"
)


这比“自然成文”更能卡住风格。

2. characteristics 最好写死“短句，不成段”

否则它有时会被写成迷你正文。

建议：

characteristics: List[str] = Field(
    default_factory=list,
    description="【兼容字段】2-3条极短短句，每条建议15-25字，只用于旧渲染链补位。不得写成长句，不得写成正文段落。"
)

我最建议你在 prompt 里补的一段

如果你只想加一小段，但效果最好，我建议补这个：

写入
PREFACE WRITING RULE

前言最重要的不是“写全”，而是“先拎住这一期最值得看的主轴”。
请像成熟新闻作者写月度综述开篇那样写：先用一句判断把全期讨论压住，再自然带出几个最有代表性的议题和情绪变化。不要把每个子议题平均着墨，也不要把后文的深读分析和风险预测提前写完。
如果你的段落读起来像“本期舆情主要呈现以下特点”或“从舆情表现看”，说明它更像报告摘要而不是前言，需要重写。

这段非常适合前言，因为它抓的是“总编视角”，不是一般写作技巧。
