你现在的问题我给你重新归纳成一句话：

不是“判不判违规”有问题，而是“判了违规以后，往哪个桶里放”不准。

所以改进重点不是继续加“从宽”，而是这四件事：

1. 先加“类目路由”，别让模型在 50 个类里直接乱选

你之前的 prompt 更像是：

先判断违规

然后直接从所有类别里选一个

这会导致模型靠字面相似乱跳类。

正确改法是：

先判一级大类，再判二级类

先让模型脑子里先过这一层：

时政有害

违法信息

诈骗信息

不良信息

人身攻击

侵权权益

不良价值

不实信息

AI生成

违规营销

涉未成年人

垃圾行为

然后只在对应大类里选子类。

你不一定要真的拆成两次调用，但 prompt 里一定要加这条规则：

在选择最终 category 前，必须先判断最匹配的一级大类，再仅在该一级大类下选择二级类别。
若无法先稳定落入某个一级大类，不得强行在全量白名单中选择最像类别，必须输出：
- is_violation=false
- category=""


这条非常重要。

2. 给高混淆类目加“映射顺序”

你之前最容易错的就是这些：

人身攻击-侮辱

人身攻击-不友善

人身攻击-仇恨歧视

不良信息-网暴

违法信息-网暴煽动

你要在 prompt 里明确写：

攻击类必须按顺序判，不得直接跳重类
当内容涉及攻击类时，必须按以下顺序判断：

1. 人身攻击-侮辱
   - 明确对象 + 直接辱骂、贬损、羞辱性称呼

2. 人身攻击-不友善
   - 明确对象 + 冒犯、阴阳、刻薄、轻度羞辱
   - 若已达到明显辱骂程度，不得降为不友善

3. 人身攻击-仇恨歧视
   - 仅适用于：明确针对民族、地域、国别、性别、疾病、生理/心理属性等群体身份进行标签化贬损、敌意、排斥或歧视
   - 对具体个人的普通辱骂、政治立场辱骂、道德谴责，不得直接归入此类

4. 不良信息-网暴
   - 属于升级类；仅在明确对象 + 明确攻击行为 + 已明显超出单次辱骂时成立
   - 需具备持续追骂、号召围攻、集中羞辱、挂人扩散、跨帖追击等要素之一

5. 违法信息-网暴煽动
   - 属于更高阶升级类；仅在出现煽动他人实施网暴、人肉、骚扰、冲击、曝光隐私时成立


这个顺序就是你之前我强调的：

先落窄类，再看能不能升级。

不是先往重类里塞。

3. 给“重类目”加升级门槛

你现在的类别不准，本质上很多是“升级过度”。

所以要单独定义：

这些类都不是默认桶

不良信息-网暴

违法信息-网暴煽动

人身攻击-仇恨歧视

违法信息-开盒

违法信息-开盒黑产

诈骗信息-*

不实信息-技术伪造

AI生成-误导

AI生成-违规内容

你要把下面这段直接加进 prompt：

以下属于升级类类别，不得作为默认归类：
- 不良信息-网暴
- 违法信息-网暴煽动
- 人身攻击-仇恨歧视
- 违法信息-开盒
- 违法信息-开盒黑产
- 诈骗信息-*
- 不实信息-技术伪造
- AI生成-误导
- AI生成-违规内容

只有当原文中存在与该类别直接对应的硬证据时，才允许归入升级类。
若升级依据不足，必须降级到更窄、更直接的类别；若仍无法唯一稳定归类，则输出空字符串。


这就是我之前说的“升级类门槛”。

4. 加一个“最低必要归类原则”

这是最重要的一句，你最好放到 prompt 很靠前的位置：

凡存在多个可疑类别时，必须优先选择“与原文行为最直接对应、解释成本最低、升级程度最低”的类别；不得为了追求更重处罚或更多法条命中而选择更重类别。


这句会显著减少：

普通辱骂 → 网暴

立场辱骂 → 仇恨歧视

普通质疑 → 造谣

普通引流 → 黑产交易

这种错分。

5. 类别复核器要专门用来“打掉重类”

你现在的 AGENT_C_CATEGORY_RECHECK_TEMPLATE 已经有了，但你之前忘了我说的关键点：

它不是用来“修饰原判”，而是用来“打掉升级错误”

你要加这段：

若当前类别属于升级类，但 quote 和 reasoning 仅能稳定支持更一般、更窄的类别，必须返回空字符串。
不得为了维持原判而继续保留更重类别。
对攻击类内容，若无法稳定支持 不良信息-网暴 / 违法信息-网暴煽动 / 人身攻击-仇恨歧视，必须视为升级失败，返回空字符串。
对不实信息内容，若无法稳定支持 不实信息-冒充 / 不实信息-技术伪造，不得勉强保留，应返回空字符串。


也就是说：

复核器的核心职责是：防止类目升级过度。

6. 第二阶段证据链也要防止“错条款把错分类说圆”

你之前给的例子里有个典型问题：

实际只是单句辱骂

第二阶段却用了“网暴人肉搜索”条款去解释

所以你要在 AGENT_C_EVIDENCE_ENRICH_TEMPLATE 里加这些限制：

laws_json 中所选条款必须与 violated_items_json 中的 category 和 quote 直接对应，不得为了补足理由而借用更重类别或相邻类别条款。
若 category 为一般攻击类，不得使用 不良信息-网暴、违法信息-网暴煽动、人身攻击-仇恨歧视、违法信息-开盒 等更重条款解释。
若 category 为 不良信息-网暴，但 quote 仅体现单次辱骂、单句贬损、情绪性咒骂，必须保持最小化说明，不得写出组织化、持续性、号召性等输入中不存在的事实。
若 category 为 人身攻击-仇恨歧视，但 quote 未明确体现群体身份攻击，不得通过 reasoning 补写群体属性。

最终你要记住的核心改法

我把之前说的压成最关键的 4 条：

第一条

先判一级大类，再判二级类。

第二条

攻击类必须按顺序映射：侮辱 → 不友善 → 仇恨歧视 → 网暴 → 网暴煽动。

第三条

重类目不是默认桶，必须有硬证据才能升级。

第四条

重类目必须二次复核，复核失败就降级或清空。

9. 一句话总结你现在该怎么改

你现在不是“审核不准”，而是“分类升级太激进”。
所以改法不是继续加从宽例子，而是：

把“类目选择”变成一个有顺序、有门槛、有复核的过程。
